# Awesome Atlas Web — PRD

## ปัญหาและเป้าหมาย

**ปัญหา:** โอเพนซอร์สที่น่าสนใจกระจายอยู่ใน README ของ GitHub Awesome lists จำนวนมาก (679 ลิสต์ที่ค้นพบ)
ผู้ใช้ต้องเปิดอ่านทีละลิสต์และไม่รู้ว่าโปรเจกต์ใดซ้ำหรือเฉพาะลิสต์ใด

**เป้าหมาย:** ให้ผู้ใช้ดูได้ว่าแต่ละลิสต์มีอะไร เทียบรายการซ้ำ/เฉพาะ เห็นอันดับพร้อมที่มาและขอบเขตข้อมูล
แล้วเปิดต้นทางหรือบันทึกเก็บไว้ได้ โดยไม่ต้องอ่าน README ทุกลิสต์เอง

## ผู้ใช้/persona

| Persona | ความต้องการ |
|---|---|
| นักพัฒนาที่หาเครื่องมือ | ค้นหาตามคำและหมวด เปิด GitHub ต้นทาง และบุ๊กมาร์ก |
| ผู้ศึกษาระบบนิเวศ | เปรียบเทียบสองลิสต์และดูอันดับการถูกอ้างถึง |
| ผู้ดูแลระบบ (owner) | ตรวจสถานะซิงก์และ coverage ของข้อมูล |

## ขอบเขต

**In scope**
- UI ภาษาไทย อ่านข้อมูลสาธารณะผ่าน `/api/v1/*` (contract `awesome.v1`)
- บุ๊กมาร์กและธีมเก็บใน `localStorage` ของ browser
- URL query ที่แชร์/โหลดซ้ำได้ เช่น `?view=list&source=...` และ `?view=rankings&ranking=daily&date=...`

**Out of scope**
- login, บัญชีผู้ใช้ และการซิงก์บุ๊กมาร์กข้ามอุปกรณ์
- การสั่ง scraping จากหน้าเว็บ (ปุ่มรีเฟรชโหลดจาก backend เท่านั้น)
- การสร้างข้อมูลที่ไม่มีจริง เช่น stars/language
- การอ่าน SQLite, lake หรือข้อมูลส่วนกลางของ Solo Empire จาก browser

## ตัวชี้วัดความสำเร็จ

- ผู้ใช้เปิดดูภายในลิสต์ เปรียบเทียบ และบันทึกโปรเจกต์ได้โดยไม่ออกจากเว็บ (เกณฑ์เชิงคุณภาพจาก `PRODUCT.md`)
- coverage ของลิสต์ที่อ่านแล้วเทียบกับลิสต์ที่ค้นพบทั้งหมด (12/679 ณ รอบแรก) **[ต้องยืนยัน]** เป้าหมายตัวเลข
- จำนวนผู้ใช้/การใช้งาน: ไม่มี analytics ในโค้ด **[ต้องยืนยัน]** ว่าต้องวัดหรือไม่

## Roadmap/phase

| Phase | เนื้อหา | สถานะ |
|---|---|---|
| Pilot | เว็บ + API บน Railway, ซิงก์ทุก 30 นาที | ออนไลน์ตาม deployment README |
| Extraction | แยกเป็น capability `awesome-discovery` | `extraction: pending` |
| ถัดไป | ขยาย coverage ลิสต์, backup/retention ข้อมูล API | **[ต้องยืนยัน]** |

## ข้อสมมติฐานและความเสี่ยง

- **[สมมติฐาน]** ผู้ใช้ยอมรับว่าบุ๊กมาร์กอยู่เฉพาะ browser เดียว
- R-01: coverage ต่ำอาจทำให้ตีความอันดับผิด — UI แสดงขอบเขตและคำเตือนแล้ว
- R-02: รูปแบบ README หรือ archive ต้นทางเปลี่ยน ทำให้ parser ของ API อ่านไม่ได้ (มี 4 ลิสต์ที่ parser ไม่รองรับแล้ว)
- R-03: `PRODUCT.md` และ README ขัดกันเรื่อง hosted deployment **[ต้องยืนยัน]**
- R-04: license ของแต่ละโปรเจกต์คงตามต้นทาง ต้องแสดงเครดิตลิสต์ต้นทางเสมอ
